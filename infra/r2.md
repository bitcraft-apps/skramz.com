# R2 media — bucket `skramz-media`

Art storage (band photos, release covers). D1 stores only the R2 **key**
(`bands.photo_r2_key`, `releases.cover_r2_key`); bytes live in R2 and are
served from the public custom domain — the Worker never proxies them.

## Bucket

- **Name:** `skramz-media` — the system's only R2 bucket.
- Created once per account (run from `api/`):
  `pnpm exec wrangler r2 bucket create skramz-media`.

## Binding (`api/wrangler.toml`)

| Binding | Kind | Target               |
| ------- | ---- | -------------------- |
| `MEDIA` | R2   | bucket `skramz-media` |

Reserved for future signed upload URLs; reads go straight to the public
host below, so the Worker spends no CPU per image.

## Key convention

- Band photos: `bands/<band-id>/<file>` (e.g. `bands/b1/photo.jpg`).
- Release covers: `releases/<release-id>/<file>`.
- Keys are path suffixes with no leading slash. `artUrl()`
  (`web/src/media.ts`) strips stray leading slashes and `encodeURI`s the key.

## Uploads (S3-compatible API / CLI)

- Least privilege: token scoped to **this bucket only** with
  **Object Read + Write** — never commit values (`R2_ACCOUNT_ID` /
  `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`).
- `r2 object` commands **require `--remote`**; without it they hit local
  dev storage and prove nothing about the bucket.

## Public host

- **Public host:** `https://media.skramz.org` (custom domain on the bucket).
- Web override: `VITE_MEDIA_URL` (default `https://media.skramz.org`).
- Round-trip proof (owner-run 2026-10-15, byte-identical): `r2 object put
  --remote` of a sentinel object, `curl` 200 GET via the public host matching
  the local bytes, then delete + 404 on re-GET.
