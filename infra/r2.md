# R2 media — bucket `skramz-media` (issues #4, #13)

Art storage (band photos, release covers). D1 stores only the R2 **key**
(`bands.photo_r2_key`, `releases.cover_r2_key`); bytes live in R2 and are
served from the public custom domain — the Worker never proxies them.

## Bucket

- **Name:** `skramz-media` — the system's only R2 bucket (region EEUR,
  created 2026-10-13).
- Created once per account: `pnpm exec wrangler r2 bucket create skramz-media`.
- Billing: free tier covers it (10 GB storage, 1M writes / 10M reads per
  month). No lifecycle rules; deletes are explicit CLI/API calls.

## Binding (`api/wrangler.toml`)

| Binding | Kind | Target              |
| ------- | ---- | ------------------- |
| `MEDIA` | R2   | bucket `skramz-media` |

`MEDIA` is the JS identifier for the `skramz-media` bucket (hyphens are not
valid binding names). Reserved for future signed upload URLs; reads go
straight to the public host below, so the Worker spends no CPU per image.

## Key convention

- Band photos: `bands/<band-id>/<file>` (e.g. `bands/b1/photo.jpg`).
- Release covers: `releases/<release-id>/<file>`.
- Keys are opaque path suffixes: no leading slash, joined onto the public
  host with one `/`. The web helper `artUrl()` (`web/src/media.ts`)
  strips stray leading slashes and `encodeURI`s the key.

## Token scope (S3-compatible API / CLI uploads)

- Least privilege: an API token scoped to **this bucket only** with
  **Object Read + Write** (no account-wide R2 Admin).
- Values live in `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` /
  `R2_SECRET_ACCESS_KEY` (GitHub secrets, local `.env`, or `wrangler
  secret`) — keys are reserved in `.env.example`; never commit values.
- Rotation: regenerate in the Cloudflare dashboard, update the secret
  store, redeploy. No code change — no secret value is checked in.

## Public host + round-trip proof (verified 2026-10-15)

- **Public host:** `https://media.skramz.org` — custom domain on the
  `skramz-media` bucket (zone `skramz.org`; wrangler domain list shows
  enabled Yes, ownership active).
- Web override: `VITE_MEDIA_URL` (default `https://media.skramz.org`).
- Proof (owner-run, byte-identical): `wrangler r2 object put --remote`
  of a sentinel object, `curl` 200 GET via `https://media.skramz.org`
  matching the local bytes, then delete + 404 on re-GET.
- CLI note: `r2 object` commands **require `--remote`**; without it they
  hit local dev storage and prove nothing about the bucket.
